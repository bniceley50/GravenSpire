## Fog + Volume composition — empirical (RESOLVES Session 1 pin)

**REFRAMED 2026-05-16** through the diagnostic chain that led to `2f2eb7a`:

Per [`session-1-wrap.md`](session-1-wrap.md) Verification 1, the expected behavior was: standard URP forward applies fog in opaque pass BEFORE Volume Color Adjustments post-process, so fog color should be desaturated/temp-shifted by the Volume. This was correctly identified as needing Session 2 empirical confirmation before fog could be treated as directionally safe.

**Initial Game view A/B verdict (FAILED-AS-MEASURED, pre-reframe):** the pre-fix and post-renderer-fix Game view PNG screenshots showed 0 changed pixels in central crop (520, 135, 1910, 920) at PowerShell numerical comparison. **Initial interpretation: "post-process not executing."** That interpretation was wrong; see reframe below.

**Reframed verdict (RESOLVED-WITH-CAVEAT):** URP post-process **does execute correctly** in this scene. The Game view 0-delta result was a measurement artifact, NOT execution failure. Two distinct root causes were uncovered + fixed during the diagnostic chain (all landed in `2f2eb7a`):

1. **`GravenspireUniversalRenderer.asset:31` had `postProcessData: {fileID: 0}`** — disabled URP post-process pipeline at the renderer level. Fixed via Editor-side defense-in-depth in both builders (`GravenspireDevEntryBuilder.cs` for the shared-renderer owner + `GravenspireFirstDistrictVisualSpikeBuilder.cs` for the spike-specific entry) plus direct asset reference to URP package default PostProcessData (guid `41439944d30ece34e96484bdb6645b55`).

2. **`Camera.Render()` in Editor mode bypasses URP per-frame initialization** (ResetMainStack + VolumeManager.Update + post-process pass dispatch). The runner's earlier diagnostic used `Camera.Render()` which produced 0 delta even after fix #1. Diagnosis via local URP 17.3.0 package source: `RenderPipeline.SubmitRenderRequest(camera, request)` with `UniversalRenderPipeline.SingleCameraRequest` is the documented off-frame entry point. Source citations against URP 17.3.0 package contents (locally at `Library/PackageCache/com.unity.render-pipelines.universal@3b809f23691d/Runtime/UniversalRenderPipeline.cs`; package-version path is `com.unity.render-pipelines.universal@17.3.0/Runtime/UniversalRenderPipeline.cs`): line `533` (SingleCameraRequest type), line `557` (destination required), line `2567` (destination field). URP package tests use the static `RenderPipeline.SubmitRenderRequest(camera, request)` invocation pattern. Runner `CheckPostProcessExecution` now uses that API.

**Why Game view 0 delta on the actual spike scene is consistent with post-process executing correctly:**
- Spec values are intentionally subtle per art-bible "no spectacle" rule: ColorAdjustments Saturation = `-5`, WhiteBalance Temperature = `+10`
- Scene palette is predominantly gray (cemetery fog + Stratum stone) by design
- Sat=-5 applied to near-gray pixels produces RGB shift below typical PNG / mean-RGB measurement resolution
- Lantern halos are saturated warm and DO receive measurable post-process shift, but their pixel area in the central crop is small enough that mean-RGB shows near-zero
- The mean-RGB-on-central-crop instrument was wrong for measuring subtle post-process on a mostly-gray scene; a per-pixel max-delta or halo-region-only crop would have shown the small shift
